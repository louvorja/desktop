Convenção

A rota é /api/v2/<recurso>, em kebab-case. O recurso é substantivo; o verbo vai no parâmetro action. Barra final não muda a rota.

GET lê, POST altera. Método errado devolve 405. Comando não alterna: repetir start mantém iniciado, não pausa.

Parâmetros têm nome em minúsculas. O action é comparado sem diferenciar maiúsculas e com espaços aparados. Parâmetro obrigatório ausente devolve 400 com code MISSING_*; presente mas inválido, INVALID_*. Parâmetro desconhecido é ignorado.

Tudo é UTF-8, na requisição e na resposta — inclusive os acentos nos valores da URL.

Formato da resposta

{ "status": "ok",    "action": "…", "code": "…", "message": "…", <campos de dados> }

{ "status": "error", "action": "…", "code": "…", "message": "…" }
CampoSignificado
statusSó "ok" ou "error".
codeSempre presente, em SCREAMING_SNAKE. É o contrato estável: decida por ele, nunca pelo texto. Em ok descreve o estado; em error, o motivo.
messageSó texto para humano. Nunca carrega dado.
dadosEm campo próprio e nomeado (musicas, time, slide), no topo do objeto. Nunca dentro de message.

Códigos HTTP

200ok404rota inexistente
400erro do cliente405método errado
401token409o estado do programa impede
500falha interna503interface não respondeu no prazo
Sobre o 503. Significa “não deu para confirmar no prazo”, e não “nada aconteceu”. O comando pode ter sido executado logo depois. Costuma indicar que o programa está com uma janela modal aberta esperando o operador.

Autenticação

O token é o mesmo configurado na aba Transmitir. Pode ir no cabeçalho, que é a forma preferida, ou na URL:

Authorization: Bearer <token>

/api/v2/ping?token=<token>

Na URL o token acaba no histórico do navegador, em log de servidor e no cabeçalho Referer enviado a terceiros. Prefira o cabeçalho quando puder.

Página servida pelo próprio programa dispensa token. Isso vale quando a conexão vem da própria máquina e o cabeçalho Origin está ausente ou é igual à origem do servidor. Uma página de terceiro aberta no navegador do operador sempre manda a origem dela, e o navegador não deixa a página mentir nisso — por isso ela precisa de token como qualquer cliente externo.

Requisições de outras máquinas sempre exigem token, mesmo com Origin forjado: um script pode escrever esse cabeçalho, então ele só vale como prova em conexão local.

O preflight OPTIONS é respondido com 204 antes da autenticação, porque ele não carrega token.

drawing-number

/api/v2/drawing-number

actionMétodoParâmetrosO que faz
statusGET—drawing, last, count, drawn
participantsGET—Lista em participants
drawPOST—Sorteia
addPOSTfrom, to ou itemFaixa numérica ou item avulso
removePOSTitemTira um item
clearPOST—Apaga todos os itens
restartPOST—Devolve os sorteados ao bolo

No add, sem from a faixa começa em 1; sem to, vai só até o from. Faixa acima de mil itens é recusada.

O sorteio responde antes de terminar. O draw devolve na hora, ainda durante a animação. Consulte status até drawing virar false para ler o número em last.

liturgy

/api/v2/liturgy

actionMétodoParâmetrosO que faz
listGETweek=1..7Itens do dia; sem week, o dia atual
openPOSTid, modeAbre o item

Cada item traz id, type, title, subtitle e done. Itens de música trazem ainda song_id, choose_song e has_playback.

O mode vale para música: normal, pb, no-audio, file, playback. Item do tipo categoria não abre nada e responde 409.

has_playback segue a regra da tela. Música indefinida ou não encontrada no banco contam como disponível. O campo responde “o programa mostraria o ícone de playback”, não “o arquivo existe”.

media

/api/v2/media

actionMétodoParâmetrosO que faz
statusGET—active, playing, file, position, duration
play / pausePOST—Retoma ou pausa
seekPOSTsecondsSalta para a posição
closePOST—Encerra a reprodução

Controla o mesmo painel da tela, servindo tanto ao player de arquivos quanto ao vídeo online. position e duration vêm em segundos. Sem nada em reprodução, status responde 200 com active:false e os comandos respondem 409.
